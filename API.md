# API Reference

## Authentication

- `AUTH_MODE=none`: all requests execute as a local admin profile.
- `AUTH_MODE=apikey`: provide `x-api-key` or `Authorization: Bearer re_...`.
- `AUTH_MODE=jwt`: provide a bearer JWT; verification uses configured issuer/JWKS.

## Rules

### Create Rule

`POST /api/v1/rules`

```json
{
  "name": "Loan origination rule",
  "environment": "dev",
  "tags": ["credit", "origination"],
  "definition": {
    "nodes": [],
    "connections": [],
    "metadata": {
      "name": "Loan origination rule",
      "environment": "dev"
    }
  }
}
```

### Validate Rule

`POST /api/v1/rules/validate`

Returns validation issues, generated expression, and compiled graph stats.

### Evaluate Rule

`POST /api/v1/rules/:id/evaluate`

```json
{
  "input": {
    "event": "application_submitted",
    "credit_score": 735
  },
  "evaluatedBy": "system"
}
```

Response:

```json
{
  "outcome": "approve",
  "passed": true,
  "conditionResults": {},
  "variableResults": {},
  "explanationTree": [],
  "executionTimeMs": 2.1,
  "traceId": "trace_123",
  "version": 3
}
```

## Generic Asset Endpoints

These resource collections follow the same contract:

- `/api/v1/variables`
- `/api/v1/connectors`
- `/api/v1/decision-tables`
- `/api/v1/scorecards`
- `/api/v1/policies`
- `/api/v1/segments`
- `/api/v1/ab-tests`
- `/api/v1/workflows`
- `/api/v1/exports`
- `/api/v1/outcome-imports`

Supported methods:

- `GET /api/v1/<resource>`
- `POST /api/v1/<resource>`
- `GET /api/v1/<resource>/:id`
- `PUT /api/v1/<resource>/:id`
- `DELETE /api/v1/<resource>/:id`

## Approvals

- `GET /api/v1/approvals`
- `POST /api/v1/approvals/:id/approve`
- `POST /api/v1/approvals/:id/reject`

## Operational Endpoints

- `GET /api/v1/dashboard/summary`
- `GET /api/v1/api-keys`
- `POST /api/v1/api-keys`
- `GET /health`
- `GET /health/ready`
- `GET /metrics`

The OpenAPI document is generated by the API app and exposed at `/docs/json`.
